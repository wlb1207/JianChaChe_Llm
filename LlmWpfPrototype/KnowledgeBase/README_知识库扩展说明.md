## 二、后续如何动态新增自己的规范或设计资料

支持 **两种接入方式**（程序会在下次检索时根据文件指纹自动重建 `Data\rag_index.json`）：

### 方式 1：轻量快速添加（放 Markdown 即可检索）
1. 在 `KnowledgeBase\` 下新建一个文件夹（如 `KnowledgeBase\Custom_Design_Notes\`，**英文/数字/下划线命名**）。
2. 直接放入任意 `.md` 文档（建议顶部写 `# 标题`、`Source: 标准或资料名`、`Clause: 条款号`，并用 `##` 二级标题分节）。
3. 程序启动或下次检索时会自动发现并索引该文件夹内的 `.md` 文档（可用于本地检索）。

### 方式 2：标准规范知识包（推荐，检索精度最高）
1. 新建标准文件夹，例如 `KnowledgeBase\JTG_D60_2015\`，在其下建 `verified\` 子目录。
2. 将原 PDF / Word 归档在该目录下，把核心设计边界拆解为若干 `verified\01_xxx.md` 卡片，并在根目录放一个 `*_key_rules.json` 索引（字段参考 `JT_T_1430_2022\jt_t_1430_key_rules.json`）。
3. 运行同步脚本自动刷新统一清单与文本提取：
   ```powershell
   python KnowledgeBase\sync_knowledge_base.py
   ```
4. 若需要将新增的公开规范也纳入**云端大模型带引用推理白名单**，可运行：
   ```powershell
   python KnowledgeBase\sync_knowledge_base.py --sync-disclosure
   ```
   确认内容无涉密信息后，将输出的 `PolicyHash` 同步到 `KnowledgeDisclosureGuard.cs` 即可（未授权的私密/自定义文档默认仅限本地检索，不会擅自外发云端）。
